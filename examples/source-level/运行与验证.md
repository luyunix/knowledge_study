# 运行与验证边界

在knowledge_study根目录使用JDK与Python3。源码按固定commit研读，实验是自己构造的机制验证，不等于部署了同版本上游服务。

```bash
mkdir -p .source-cache/experiments
javac --release 17 -d .source-cache/experiments examples/source-level/HandwrittenLru.java examples/source-level/LeasedVersion.java examples/source-level/CoverageMechanics.java examples/source-level/BinaryCompatibilityLab.java
java -cp .source-cache/experiments CoverageMechanics
java -cp .source-cache/experiments BinaryCompatibilityLab
python3 examples/source-level/coverage_models.py
python3 examples/source-level/project_contracts.py
```

本轮在现有JDK21运行，以--release 17编译；不等于已在JDK17二进制上验证。BinaryCompatibilityLab在独立临时目录编译API与插件，真实观察NoSuchMethodError，再保留旧方法描述符验证兼容；它不覆盖Maven依赖解析的全部规则。

CoverageMechanics包含10万步独立LRU顺序模型、8线程指针不变量、排空门边界和97,655个最大子数组输入。并发压力检查不是完整操作历史的线性化验证器；排空门是单进程实现，不是注册中心传播测试。

coverage_models.py覆盖DAG fork/join、重复完成、旧attempt、上游失败传播、环检测、稳定分片、容量计算、状态schema迁移、向量空间混用反例、核时与SQLite租约CAS。SQLite采用内存库和确定性顺序竞争，不宣称验证多机时钟、网络分区或外部服务恰好一次。

project_contracts.py使用Python标准库，实际导入并reload临时模块、启动隔离子进程；其余为有限字段摘要、SDK事件序列、CLI返回、fixture、构建Job账本及区间清单的参考模型。运行环境是本机Python，不等于运行CPython 3.12二进制。没有调用真实Codex、pip、Kubernetes、ODPS或OSS；不证明生产接入、隐私合规、分布式一致性或容量已验证。

仍需真实环境演练：注册/地址传播、Pod排空、长流取消、HPA指标缺失、OOM、消息重投、外部幂等与授权、索引回填切换。文中的线上诊断命令未针对真实进程或数据库执行。

## 补深算例的独立复核

运行 `python3 examples/source-level/depth_review_models.py`。8组测试核对PFor两个分支的载荷记账与数值还原、HNSW教学队列的漏近邻反例、切分重叠与存储数字、RRF及裁判混淆矩阵、追赶/排队/峰值算式、控制代次与DAG重复事件、混合排序游标以及SRM/LFU算术。

它只使用Python标准库。PFor部分不是Lucene兼容编码器，HNSW部分不是完整图索引；没有运行Eino，也没有验证Redis/MySQL/Kafka/Proxy真实网络并发与持久化。通过代表文中这些小输入下的算术和状态模型一致，不代表所有源码分支或线上性能已经验证。
